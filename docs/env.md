# Environment variables

Every variable the runtime reads goes through one table, `RECOMP_ENV_KEYS` in toolkit `src/platform/recomp_env.h`, and is read once at startup (`recomp_env_init`, called first in `main`) and cached. A lookup is an array load, so call sites in hot paths cost nothing. There are three tiers:

- **Config** (60): documented knobs, each its own variable (`RECOMP_PB_BACKEND=d3d11`). Thirteen of them belong to the toolkit's enhancements layer (`RECOMP_CONFIG`, `RECOMP_RENDER_SCALE`, `RECOMP_RENDER_ANISO`, `RECOMP_DISPLAY_ASPECT`, `RECOMP_DISPLAY_MOVIE`, `RECOMP_DISPLAY_OVERSCAN`, `RECOMP_PRESENT_FILTER`, `RECOMP_PRESENT_FULLSCREEN`, `RECOMP_PRESENT_PACING`, `RECOMP_PRESENT_SURFACE`, `RECOMP_TEXTURES_PACK`, `RECOMP_TEXTURES_FONT`, `RECOMP_TEXTURES_TEXT`) and exist only when it is built (`XBOXRECOMP_ENHANCE`, on by default in this project); each overrides its key in the player's `config/config.toml`, which overrides the shipped `config.default.toml` beside the executable (toolkit `docs/runtime/config.md`). Every enhancement key defaults to stock except `present.pacing`, which defaults to `sleep` (fps-pacing D9). The game's keys, `RECOMP_FPS_MODE`, `RECOMP_GLOW`, `RECOMP_GLOW_INTENSITY` and the eight `RECOMP_CAMERA_FREE*`, override `fps.mode`, `fx.glow`, `fx.glow_intensity` and the `camera.*` keys the same way and are read only with the layer. `RECOMP_KEYBOARD` and `RECOMP_MOUSE` override `input.keyboard` and `input.mouse` the same way when the layer is built, and are the only switch without it.
- **Trace** (62): log and report toggles, one comma list: `RECOMP_TRACE=flip,tex,heap=0x80123000`. Printing only; nothing changes behaviour. Every trace key is off when unset except `missing`, the missing-game-file report, which is on unless `missing=0`.
- **Debug** (104): hacks, A/B switches, experiments, dumps, watchpoints, one comma list: `RECOMP_DEBUG=pb_fast=0,fb_dump=/tmp/f_,fb_dump_at=61,121`. Anything that changes behaviour, writes files or installs machinery (a watchdog, a thread dumper) is here.

List syntax: `key` means `1`, `key=value` sets a value, and a later entry wins. Only keys whose values hold commas (`fb_dump_at`, `peek`, `peek_chain`, `px`, `px_consts`, `dsp_ack`, `apu_dsp_ack`, `poke`, `window_shot`, `pad_script`, `vsh_const_prog`, `fb_dump_prog`, and the game's `mem_dump` and `pad_peek`) take the fragments after them as part of the value, so `fb_dump_at=61,121,181`, `peek_chain=0x1315A8,8,0x10,0` and `px=10,20;30,40` each read as one value. After any other key, a fragment that is not a key gets the unknown-key warning, so a typo such as `d3d11_dump=Z:\d,pb_fsatt=0` is reported, not glued onto the path. `RECOMP_TRACE=help` (or `RECOMP_DEBUG=help`) prints the table. A key given in the wrong list is accepted with a note. An unknown key is ignored with a warning.

Rows marked (game) are this game's own keys. They are defined in `cat:src/env/recomp_env_game.h`, which the toolkit table pulls in through its `RECOMP_ENV_GAME_KEYS` hook (CMakeLists.txt sets `RECOMP_ENV_HAVE_GAME_KEYS`); the toolkit itself no longer knows them.

**Old names still work.** Each replaced variable is an alias that prints one line at startup, e.g. `[ENV] RECOMP_FLIP_LOG is deprecated; use RECOMP_TRACE=flip`. When both spellings are set, the new one wins. Defaults are unchanged except two config knobs that now default on: `RECOMP_PB_EXEC` and `RECOMP_AC97_READY` (x86-64 Windows/Proton, and macOS/Linux arm64); `=0` turns either off. The toolkit also defaults `apu_dsp_ack` to `auto`, the GP doorbell found from `GPSADDR` (see below), and this game states `guest_cpus=one` as a game default. Keys whose old variable defaulted on (`pb_vsh`, `pb_rc`, `pb_fast`, `pb_bilinear`, `pb_clip`, `fast_kick`, `d3d11_memo`, `apu_mixdown_all`) are still switched off with `=0`.

Scripts: `blinx2 bench` and `golden.py plan` merge `RECOMP_TRACE` / `RECOMP_DEBUG` from several sources (a scenario's pins, `BENCH_ENV`, `BENCH_FRAMES`) by joining them with commas. Any other variable is replaced, as before.

Code that sets a variable after startup uses `recomp_env_set(RENV_X, value)`; tests that `setenv` call `recomp_env_reload()`. The generated `recomp_stubs_unresolved.c` still calls `getenv("RECOMP_STUB_LOG")`, so `recomp_env` exports that variable when `RECOMP_TRACE=stub` is set.

## Settings files (`config.default.toml`, `config.toml`)

The settings live in two files. `config.default.toml` ships beside the executable (inside `Contents/Resources/` in the macOS app) and holds the defaults; an install or upgrade replaces it and the game never writes it. The player's `config/config.toml` holds only what they changed, and nothing overwrites it. The lookup is env over `config/config.toml` (or the `RECOMP_CONFIG` file) over `config.default.toml` over the code default; this game passes no title, so there is no per-title file (toolkit `docs/runtime/config.md`). The toolkit's layer reads its keys (`[render] scale`, `[display] aspect`, `hud`, `movie`, `[present] filter`, `fullscreen`, `pacing`, `surface`, `[textures] pack`, `font`, `text`) and this game adds its own tables to the same files, bound to the variables above with `enhance_cfg_bind_env` (`src/main.c`, and the `camera.*` keys in `src/free_camera.c` through the mod API):

| Key | Type | Values | Stock | Env |
|---|---|---|---|---|
| `fps.mode` | string | `"lock30"` (stock); `"lock60"` and `"free"` are not available and run `lock30` with one line | `"lock30"` | `RECOMP_FPS_MODE` |
| `fx.glow` | string | `"on"` (stock), `"off"`: the post-mode-3 glow pass drawn with weight 0 | `"on"` | `RECOMP_GLOW` |
| `fx.glow_intensity` | float | `0.0` to `2.0`, a scale of the glow layer | `1.0` | `RECOMP_GLOW_INTENSITY` |
| `camera.free` | string | `"off"` (stock), `"on"`: arm the free camera | `"off"` | `RECOMP_CAMERA_FREE` |
| `camera.free_speed` | float | `0.05` to `20`, fly speed multiplier | `1.0` | `RECOMP_CAMERA_FREE_SPEED` |
| `camera.free_look_sens` | float | `0.05` to `10`, look rate multiplier | `1.0` | `RECOMP_CAMERA_FREE_LOOK_SENS` |

## Launcher variables

The packaged launchers (`BLiNX2.app`, `BLiNX2.exe`, the steamos `launch.sh`)
read these before the game starts; the game itself never sees them, so they
are not `recomp_env` keys.

| Name | Where | Meaning |
|---|---|---|
| `BLINX2_DATA_DIR` | macOS and Windows launchers | user-data root instead of `~/Library/Application Support/BLiNX2` or `%LOCALAPPDATA%\BLiNX2` (`hdd/`, `config/`, `logs/` follow it). Tests set it to a scratch folder so they never touch the player's data |
| `BLINX2_ROOT` | steamos `install.sh` | install and data root instead of `~/Games/BLiNX2` (same as `--root`) |
| `LOG_KEEP` | all launchers, from `launch.env` | game logs kept in `logs/` (default 10) |
| `PROTONPATH` | steamos `launch.sh`, from the environment or `config/launch.env` | the Proton build `umu-run` uses (default: the GE-Proton release the CLI pins, installed by `install.sh`; `GE-Proton` follows the newest). The environment's value wins over the default; `launch.env.default`'s is ignored |
| `UMU_RUNTIME_UPDATE` | umu-run, steamos `launch.sh`, from `config/launch.env` | `1` checks the Steam Linux Runtime for updates at every launch, `0` never; unset, the launcher checks only on the first launch after an install or rollback |
| `UMU_RUN` | steamos `launch.sh`, from `launch.env` | the `umu-run` to use, before the search (PATH, `~/.local/bin`, the installer's copy) |
| `LAUNCH_NOTICE` | steamos `launch.sh`, from `launch.env` | `0` turns off the notice shown while a launch may download (a missing runtime, the update check after an install, a codename `PROTONPATH`, a new prefix; default on) |
| `LOG_MAX_MB` | steamos `launch.sh`, from `launch.env` | at launch, a log in `logs/` over this many MB is cut to its first and last halves (default 64; `0` keeps them whole) |
| `PROTON_LOG, PROTON_LOG_DIR` | Proton, steamos `launch.sh` | `PROTON_LOG=1` in `launch.env` writes Proton's own log; the launcher points `PROTON_LOG_DIR` at `logs/` |
| `NOTICE_MAX` | steamos `launch.sh`, from `launch.env` | seconds the launch notice stays up at most (default 1200) |
