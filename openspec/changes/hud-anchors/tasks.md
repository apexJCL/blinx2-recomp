## 2. The HUD mapping framework (toolkit and CLI; about 4 days)

- [ ] 2.1 Toolkit: the DEBUG keys `hud_capture=<dir>`, `hud_capture_at=<from>:<count>` (guest frames) and `hud_capture_table=<path>` (design A15). Level 1 at `hud_apply`; level 0 at the D3D draw entries the table lists under `[capture] draws`, hooked as slots, with a scan of the stack for return addresses inside the code sections (cat `spike/hud-locate` adc8034 `hud_calls` as the starting point). DEBUG rows in `recomp_env.h`; a ctest over a synthetic capture.
- [ ] 2.2 CLI: the `hud-map` command group (package `hudmap/`) in `main.py`, beside `bench`, `public` and `wizard`, listed with the developer commands, apart from the player's `enhance hud`; the optional `game.toml` `[hud]` table (`table`, default `config/hud.toml`; `scenarios`), with its schema entry in `manifest.py` (in `OPTIONAL`) and a section in `docs/manifest.md`. `hud-map capture SCENARIO [--level 0|1] [--frames FROM:COUNT] [--out DIR]` runs the scenario at stock aspect with the capture keys and `hud_capture_table` set to the game's table; `--out` defaults to `dist/hud-map/<scenario>/`.

- [ ] 2.8 Gates: toolkit as in 1.10 for 2.1 (stock goldens: the key is unset); CLI `uv run pytest tests`, ruff check and format. 2.1 to 2.3 merge only after 1.1, 1.2 and 1.5 (capture needs the canvas, the table, the chain and the active flag); 2.4 to 2.6 after section 1.
